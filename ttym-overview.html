합쳐지면

에이전트 열댓 개를 한 화면에서 굴리고, 코어를 업그레이드해도 대화가 끊기지 않는 작업 환경.

웹에서 보다가 CLI로 질문을 던지고, 스크립트가 같은 세션에 붙어 자동화한다 — 셋이 같은 계약을 쓴다.

이 구조라서 되는 것

  • 무중단 업그레이드 — PTY가 서버 밖에 있다
  • 이번 응답만 받기 — 서버가 셀을 알아 구간을 자른다
  • 여러 얼굴 — 웹·앱·CLI가 한 코어를 공유
  • 자동화 — UI 없이 CLI로 전부 조작된다

지금의 계획

1
레이아웃 트리 보존 — 지금은 멤버를 추가할 때마다 중첩·비율이 평탄해진다. 프로덕션 7/7이 이미 손상
2
controller lease — 새 접속이 기존 서버를 조용히 밀어낸다. 교체 중 세션 하나를 이렇게 잃었다
3
체크포인트로 복구 — 571KB 렌더 스냅샷을 이미 쓰고 있으면서 교체 때는 버리고 1MB raw만 쓴다
4
패키지 경계 정리 — protocol 신설, CLI 승격. 위 셋이 끝난 뒤
·
플러그인 API·저장소 추상화·holder 셀 모델은 하지 않는다. 두 번째 구현체가 실재할 때까지
Rust holder + TypeScript 코어 · pnpm workspace · ~/.ttym 런타임 · launchd 관리
